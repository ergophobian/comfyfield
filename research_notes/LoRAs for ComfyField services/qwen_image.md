# LoRAs for the Qwen-Image family (Qwen-Image 2.1, Qwen-Image-Edit 2511, Qwen-Image-Layered) mapped to ComfyField services

Checked 2026-10-19. Every LoRA below was opened on its Hugging Face (HF) or Civitai page (model card or API record) on that date. Search snippets were not used as sources.

How to read the numbers:
- HF "30d" is downloads in the last 30 days, "all" is all-time downloads, "likes" is HF likes. Pulled from `https://huggingface.co/api/models/<repo>?expand[]=downloadsAllTime&expand[]=downloads&expand[]=likes`.
- Civitai "dl / up" is the model-level download count and thumbs-up count. A Civitai model often holds versions for several base models (Flux.2 Klein, Krea 2, Z-Image), so the model-level count is not Qwen-only. Where the API gives it, "Qwen-version dl" is the count for the Qwen version only. Civitai's public API gives thumbs-up counts, not star ratings.
- Civitai base model strings: `Qwen` covers Qwen-Image, Qwen-Image-2512 and Qwen-Image-Edit (original, 2509, 2511) together; `Qwen 2.1` covers Qwen-Image-2.1 (generation and edit) ([Civitai API, Qwen](https://civitai.com/api/v1/models?types=LORA&sort=Most%20Downloaded&nsfw=false&limit=100&baseModels=Qwen); [Civitai API, Qwen 2.1](https://civitai.com/api/v1/models?types=LORA&sort=Most%20Downloaded&nsfw=false&limit=100&baseModels=Qwen%202.1)).
- Excluded per the brief, not listed below: NSFW-focused LoRAs (for example the many `qwen-image-edit-plus-nsfw-lora` clones on the 2511 adapter list), LoRAs of real people (for example `joyfox/Qwen-Image-Liuyifei-LoRA`), LoRAs named after living artists (for example "Manga style (Naoki Urasawa)"), and "AI influencer [SFW+NSFW]" character LoRAs ([HF 2511 adapter list](https://huggingface.co/api/models?filter=base_model:adapter:Qwen/Qwen-Image-Edit-2511&sort=downloads&limit=100); [HF Qwen-Image adapter list](https://huggingface.co/api/models?filter=base_model:adapter:Qwen/Qwen-Image&sort=downloads&limit=100)).

## 1. Which Qwen-Image-Edit LoRAs are most used and best regarded for each ComfyField service, and which exist for Edit 2511 versus only 2509 or the original Edit?

### Takeaway
The Edit 2509/2511 ecosystem is large and mostly Apache-2.0 or MIT, and most top tasks (multiple angles, relight, light transfer, fusion, white-background-to-scene, try-on, next scene, upscale, object removal, face/head swap) have a 2511 or 2509 LoRA with real adoption. Qwen-Image-2.1 is a new 7B architecture, so no 2509/2511 LoRA loads on it; its own LoRA ecosystem is one month old but already covers outpaint, restore, outfit swap, consistency, camera angles, next scene, head/body swap, watermark removal and character sheets. Most ComfyField Qwen services run on Qwen-Image 2.1, so only the 2.1-native LoRAs apply to them as wired today.

### Cited Findings

#### Base-model facts that decide compatibility
- Qwen-Image-2.1 is "a unified text-to-image generation and image editing model" with "7B parameters in its visual generation component (32 Single-Stream DiT layers)", supports up to 10 reference images, and local edits "via circles, painted annotations, or separate masks"; licence is the Qwen Research License — [Qwen/Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1)
- Qwen-Image-2.1-Turbo is "an accelerated checkpoint of Qwen-Image-2.1 ... with 8 denoising steps", CFG 1 by default, same Qwen Research License — [Qwen/Qwen-Image-2.1-Turbo](https://huggingface.co/Qwen/Qwen-Image-2.1-Turbo)
- Qwen-Image / Qwen-Image-2512 / Edit are 20B MMDiT models (Comfy template text: "Qwen-Image's 20B MMDiT model"; the 2512 advertisement LoRA card says "Qwen-Image-2512 (20.5B parameters)") — [Comfy template index](https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/templates/index.json); [RayyanAhmed9477/qwen-image-2512-lora-advertisement](https://huggingface.co/RayyanAhmed9477/qwen-image-2512-lora-advertisement)
- 2.1 LoRA authors state the break directly: the 2.1 Stop-Motion LoRA "is not an adapter for older Qwen-Image releases"; the 2.1 Next-Scene LoRA was "retrained natively on the newest Qwen image" model — [ProCreations/stopmotion-consistency-v1-lora](https://huggingface.co/ProCreations/stopmotion-consistency-v1-lora); [akhaliq/Qwen-Image-2.1-Next-Scene-LoRA](https://huggingface.co/akhaliq/Qwen-Image-2.1-Next-Scene-LoRA)
- Qwen-Image-Edit-2511 "integrates selected popular LoRAs directly into the base model", with "Lighting Enhancement LoRA" and "generating new viewpoints" as the named examples; it also claims less image drift and better single- and multi-person consistency — [Qwen/Qwen-Image-Edit-2511](https://huggingface.co/Qwen/Qwen-Image-Edit-2511)
- Comfy-Org mirrors six community Edit 2509 LoRAs in its own repo (Multiple-angles, Anything2RealAlpha, Fusion, Light-Migration, Relight, White_to_Scene; 236–610 MB each) — [Comfy-Org/Qwen-Image-Edit_ComfyUI split_files/loras](https://huggingface.co/Comfy-Org/Qwen-Image-Edit_ComfyUI/tree/main/split_files/loras)
- Comfy-Org's 2.1 repo ships one LoRA, an extracted Turbo LoRA (`qwen_image_2.1_turbo_lora_avg_rank_178_bf16.safetensors`, 913 MB) and a Fun ControlNet Union model patch — [Comfy-Org/Qwen-Image-2.1](https://huggingface.co/Comfy-Org/Qwen-Image-2.1)

- prithivMLmods' 2511 LoRAs (Object-Remover, Object-Adder, Unblur-Upscale, Studio-DeLight, Extract-Outfit, Polaroid, Anime, portrait LoRAs) each state "Compatible with versions 2509 and 2511" — [prithivMLmods/Qwen-Image-Edit-2511-Object-Remover](https://huggingface.co/prithivMLmods/Qwen-Image-Edit-2511-Object-Remover)

## 3. Which speed LoRAs exist for Qwen-Image 2.1 and Edit 2511, and what are their quality trade-offs?

### Inferences
- For ComfyField on 2.1, the lowest-risk speed path is the official Turbo checkpoint (or Comfy's extracted Turbo LoRA) because Comfy ships native templates for it; Viggle v0.3 r128 is the most-adopted third-party option. Keep 40-step base (or Viggle's 9-step mode outside ComfyUI) for text-heavy Ads stills.
- For 2511 formats, default to Lightning 8-step; use 4-step only for previews; test each task LoRA with Lightning, because some (try-on) degrade with it.

### Gaps
- No independent benchmark compares the 2.1 distills (Viggle vs Pruna vs lightx2v vs Fun-Acc vs Turbo) on edit tasks; each card reports only its own tests.
- lightx2v's 2.1 Lightning card lists no licence and no trade-offs.

## 4. For every pick: does it load with ComfyUI's standard LoRA loader, and does it need a special prompt pattern?

### Takeaway
Nearly all Edit 2509/2511 and Qwen-Image 2.1 LoRAs in this catalog load with ComfyUI's standard `LoraLoaderModelOnly` placed after the diffusion model loader; most need an exact trigger sentence and a fixed image order. The exceptions are a short list of research adapters that need their own pipeline or custom nodes, Pruna's 2.1 files (alpha ignored by ComfyUI), and the 2.1 distills that need exact sigma schedules.

### Cited Findings
- Comfy's own templates load community Qwen LoRAs with two chained `LoraLoaderModelOnly` nodes (task LoRA + Lightning), verified in the 2509 Relight, 2509 Fusion ("Relight Composited Product") and 2511 Multiple-Angles template JSONs; Comfy also ships LoRA templates for Qwen-Image illustration, SYSTMS ACTION and INFL8 — [Relight template](https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/templates/image_qwen_image_edit_2509_relight.json); [Multi-angle template](https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/templates/template_qwen_multiangle.app.json); [Comfy template index](https://raw.githubusercontent.com/Comfy-Org/workflow_templates/main/templates/index.json)
- kingroka's Edit LoRAs: "the official Qwen Edit Workflow template ... with an extra LoadLoraModelOnly node" — [Civitai 1940532](https://civitai.com/models/1940532); svntax: in the 2511 template "you'll have to edit the subgraph to add a new node for loading this LoRA" — [svntax-dev](https://huggingface.co/svntax-dev/pixel_spritesheet_4walk_combat_32x48_v1)
- 2.1 LoRAs in ComfyUI key format load with `LoraLoaderModelOnly` on Comfy-Org 2.1 weights, fed through `TextEncodeQwenImage21` with the latent taken from the encoder: ausboss Consistency ("all 384 tensors load"), Outfit Swap (ComfyUI 0.38+), Outpaint, Restore; Gogodr pano360; houseofboern sheets; BFS body swap — [ausboss Consistency](https://huggingface.co/ausboss/Qwen-Image-2.1-Consistency-LoRA); [Gogodr pano360](https://huggingface.co/Gogodr/qwen-image-2.1-edit-pano360-lora); [BFS body guide](https://huggingface.co/Alissonerdx/BFS-Best-Face-Swap/blob/main/docs/qwen-image-2.1-body.md)

  - PixelSmile: community node `ComfyUI-PixelSmile-Conditioning-Interpolation` — [PixelSmile](https://huggingface.co/PixelSmile/PixelSmile)

  - Stable-Layers (on Qwen-Image-Layered): PEFT adapter run through Stability's code; Heun, 50 steps, CFG 1, 640 px, 4 layers; "a non-Heun sampler will garble" output — [StabilityLabs/Stable-Layers](https://huggingface.co/StabilityLabs/Stable-Layers)
  - Marigold v2 (depth/normals/albedo on 2509) and WindowSeat (reflection removal on 2509) ship transformer LoRAs with VAE-decoder weights or precomputed text embeddings for their own inference code — [Marigold v2](https://huggingface.co/huawei-bayerlab/marigold-v2-0); [WindowSeat](https://huggingface.co/huawei-bayerlab/windowseat-reflection-removal-v1-0)

### Inferences
- A ComfyField "LoRA preset" record needs at least: base model id, LoRA file and strength, trigger template with slots, image order, mask colour convention, steps/CFG/sampler and whether Lightning/Turbo is allowed. Most picks fit this record without custom nodes.

### Gaps
- Whether Comfy Cloud pre-hosts any of these LoRAs beyond the Comfy-Org mirrors was not verified; the internal lineup note says Cloud "imports LoRAs" but has no training ([image_and_video.md](D:/Code/comfyfield/research_notes/Open%20weight%20model%20lineup/image_and_video.md)).
- ComfyUI loading of DoRA weights and of Pruna's original (unconverted) files at correct scale was not tested here.

## 6. Novel or interesting: capabilities that could become new ComfyField services
