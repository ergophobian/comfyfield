# Ads and marketing studios

Audited against the repository's Higgsfield capture from October 16, 2026. No login, paid generation or live model call was used for this implementation.

## Observed structure

Sources: [audit overview](Higgsfield%20feature%20audit/README.md), [route index](Higgsfield%20feature%20audit/route-index.md), [tools and studios](Higgsfield%20feature%20audit/sections/02_tools_and_studios.md), [apps](Higgsfield%20feature%20audit/sections/03_apps.md), [presets](Higgsfield%20feature%20audit/sections/05_presets.md), and [platform](Higgsfield%20feature%20audit/sections/08_platform.md). The relevant tool headings are Click to Ad, Marketing Studio, and Ads Studio and Ad Multiplier. Issues [29](https://github.com/ergophobian/comfyfield/issues/29) and [30](https://github.com/ergophobian/comfyfield/issues/30) supply the local acceptance criteria.

- Ads Studio (`/ads-studio`) has two tools. Create ads starts with a business link or manual brand kit, selects products, then generates up to 20 still ads per product. The kit contains logo, hex palette, fonts, tone, audience, description and selling points. Ad Multiplier starts with a 4–30 second reference video, product/cast/location references, direction and a quality control; it changes hooks, scripts and calls to action.
- Marketing Studio (`/marketing-studio`) is template-first: category cards, a composer with product/avatar/brand slots, and a template gallery filtered by media and category. Categories include product shot, motion, creator video, social, ads, posters and marketplace. Product shots have studio/lifestyle/with-model variants; creator videos include faceless/talking-head/silent variants. Users may instead write a free brief.
- Click to Ad (`/apps/link-to-video-ad`) redirects into Marketing Studio. It imports product name, description, up to eight photos, logo and colors; the user reviews these, picks a template and generates variants. The audit does not expose the private import or orchestration implementation, and the product-ad apps rarely name their underlying model.
- Product apps (bullet-time packshot, macro product, billboard, fridge, truck and other commercial looks) share the pattern product photo → template → image/video choice → output. Preset collections expose commercial camera moves and creator-style scenes. The catalog has separate image and video marketing presets.
- Finished outputs go to Assets/history. Cost appears before generation. Marketing duration evidence differs between sources: the help center says 15 seconds and one blog says 30. This implementation offers up to 15 seconds and does not claim 30-second marketing renders.

## ComfyField flow

Keep the existing light-glass layout, category gallery, composer, brand controls and editable storyboard. Use ComfyField copy and media. Routes remain `/ads` and `/marketing`.

1. Read one public product/business page with `POST /api/ads/import`. Extract structured product data, social metadata and title/description fallbacks; retain up to eight candidate images, an icon/logo candidate, theme/inline colors, brand and price. No scripts execute and no linked pages/stylesheets are crawled. Copy and palette are best-effort metadata, not inferred product facts.
2. Import supported raster photos locally and show editable product/brand values. Users may replace photos, edit colors, use Library products/brands, or enter details manually. Neither an import nor drafting silently creates a saved Library product or brand kit.
3. Draft through `gens.generateFormat`: one Writer node produces a concept, headline, call to action and scene instructions from every page value, including storyboard edits and references. Page content is explicitly untrusted data and the writer may use only supplied claims. A Writer Send boundary and a native Approve node block all rendering.
4. Let the user edit the draft and click **Approve and render**. Each variant binds the reviewed script together with its own canvas/variant/angle direction into the workflow's prompt field. Changing inputs invalidates the draft; drafting again is required. Send does not rerun completed outputs.
5. Stills use `qwen2511_ad`, a derivative of the existing Qwen Edit 2511 graph with an independent output canvas. Every file/LoRA is flagged available on Comfy Cloud. The newer Qwen 2.1 edit graph requires a Pod, so it is not selected. Headline/call-to-action text is requested in the image generation prompt; exact typography needs visual review and is not a deterministic vector overlay.
6. Videos use `h3_studio_ad`, derived from `h3_product_ad`, adding optional presenter and logo references. Product/presenter/logo occupy picture slots 1/2/3. The approved storyboard describes shots within one generated clip. Reference-ad recreation uses the existing `bernini_recreate_ad` and preserves its source resolution; no unsupported quality override is shown.
7. An optional uploaded voiceover is stored locally and mixed into each completed video through `/api/stitch` → `core.stitch` → `renderStitch`. Original clips and mixed exports remain in the Library. Stitch mixes with existing audio and trims/pads the track to the clip; this is not voice cloning or lip synchronization. Variants are alternatives, so they are not concatenated as if they were consecutive shots.
8. The shared generation adapter persists every rendered result in the Library. The studio batch board shows progress/errors and lets users approve individual outputs. Result approval never submits or publishes an ad.

## Fetch boundaries

The reader uses only public HTTP(S) GETs on standard ports, with no credentials. It rejects loopback/private/link-local/reserved addresses, unusual numeric loopback forms, mapped IPv6 and mixed public/private DNS answers. DNS results are pinned to the socket to prevent rebinding. Each redirect is revalidated, with at most four redirects. One ten-second deadline covers resolution, redirects and streaming for each resource. HTML is capped at 2 MB; each raster image at 8 MB. Photos are fetched sequentially, capped at eight plus a logo. HTML content type, upstream errors, blocked/empty pages, image type/signature and streaming size are checked. Image failures leave editable fields and an explanatory warning.

## Validation and scope

`ads-checks.mjs` checks the guarded transport and streaming fixture, redirect attacks, extraction, local media, cloud availability, Writer/Approve boundaries, edited scripts, canvas/variant settings, product/presenter references and Library metadata. `ads-ui-checks.mjs` serves the production build against an isolated mock API with environment-file loading disabled, using Windows headless Chrome. It covers both imports, bad-page recovery, edited script/storyboard values, zero renders before approval, still/video generation, voiceover mixing, result approval and Library after reload. Mock screenshots are under `screenshots/ads-studios/`; they prove the flow and layout, not generation quality.

No live generation, key lookup, upload to an external service, publishing, push or pull request is part of this lane. Writer use requires a supported configured prompt provider; rendering requires the user's Comfy connection. Paid provider quality, reliable generated lettering, dedicated creator voice/lip-sync formats from issue 30, site-wide catalog discovery, external-stylesheet palette extraction, editable poster layers, a virality predictor and provider price estimates remain outside this implementation. No RunPod manager or routing code was changed.
